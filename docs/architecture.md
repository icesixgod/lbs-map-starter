# 地图与建筑交互架构

## 数据路径

```text
OpenFreeMap 矢量瓦片 / Overpass
  → scripts/map-upstream.cjs           取数、重试与数据源切换
  → scripts/vector-map-source.cjs      瓦片解码、跨边界轮廓拼接
  → scripts/district-map-service.cjs   请求合并、磁盘缓存与增量响应
  → /api/map                          JSON / NDJSON
  → src/lbs-map-work.js                Worker 准备与增量合并
  → src/lbs-map-buildings.js           建筑身份匹配与保留
  → src/coop-district-scene.js         可见几何与选择索引
  → src/map-client.js                 界面、视野与当前选择
```

初始地图由构建脚本嵌入 HTML，页面解析时即可准备模型；本地服务可用时同时开始在线补载。浏览器端不需要引用父目录或外部部署项目。

## 加载与缓存

道路与建筑的加载窗口分别规划。视野移动时沿移动方向预取，建筑在增量数据到达后补入当前场景；相邻下载窗口交接时处理已收到的批次，并取消过期工作。视野、解析与建模中的取消信号用于阻止晚到结果覆盖当前地图。

在线磁盘缓存默认位于 `.cache/maps/`，基础地图位于其 `base/` 子目录。原始矢量瓦片在进程内复用，缓存目录不属于源码分发。生成页面位于 `dist/`，也不属于版本控制内容。

## 建筑身份

瓦片边缘的同一楼体在轮廓完整后建立模型；未知的边缘碎片不作为可选的完整建筑显示。模型注册表使用来源别名及轮廓指纹，并结合位置、面积与重叠程度匹配已有实体，尽量保持轮廓、高度、材质变化和选择身份稳定。

这是一种针对当前会话的显示／交互身份。它包含几何匹配规则，不能充当跨地图版本、跨设备或跨供应商的永久建筑数据库。首次建立错误楼体时，保留既有模型也可能保留旧数据；需要更新策略时应明确处理数据版本。

不同高度的重叠建筑部件仍可独立保留，不能将所有重叠轮廓简单合成一栋最高的楼。庭院等空洞同时用于渲染和点选。

## 2D、3D 与选择

三维场景使用 Three.js 正交相机，二维视图使用 SVG。两种视图共享 WGS84 数据和建筑选择区域。屋顶／立面射线命中与地面轮廓选择共同提供交互，选择后由 `map-client.js` 更新高亮、列表和详情。

`src/map-gestures.js` 统一处理两种视图的单指拖动、双指缩放、指针捕获与取消。缩放围绕双指中心，松开一指后可继续拖动，手势结束不会触发建筑点选。

GPS 由用户操作启动，位置更新后平滑跟随，保留当前缩放并尊重正在进行的手动拖动。

## 高度与外观

- 高度使用地图 `height`；缺失时使用 `building:levels × 3.2`，再缺失时按用途和固定 ID 规则估算。
- 矢量瓦片的 `render_height` 会转换为高度字段；该上游值也可能是推算结果。
- 当前楼高上限为 220 米，交通设施还有展示简化。逻辑在 `src/coop-local-places.js` 和 `src/coop-district-scene.js`。
- 窗户、外墙和屋顶设施是程序化材质／几何表现，不是建筑测绘或真实影像。

## 保留的兼容字段

内部模块仍使用 `coop-*` 文件名；地理数据结构中的 `gameNodes` 字段用于现有 POI 映射兼容。默认地图与回归地图不含旧玩法标记；运行入口没有任务、战斗、背包或存档系统。

## 验证范围

`npm run verify` 覆盖地图与水域轮廓、建筑身份、庭院、点选、流式增量、请求取消、缓存和 GPS 跟随，并检查生成 HTML 和内嵌 Worker 的语法。测试使用必要 JSON 样例和模拟网络；真实公共地图服务、设备 GPS、浏览器 GPU 性能仍需按部署环境验证。
